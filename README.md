# RecoverAI: Voice Agent for Autopay Recovery

RecoverAI is an end-to-end hackathon demonstration of a merchant-operated, AI-assisted payment recovery workflow. It starts from 10 fictional failed-autopay records, launches a real browser voice conversation through ElevenLabs ElevenAgents, records the outcome and transcript, opens a hosted Razorpay test checkout, and counts revenue as recovered only after payment confirmation.

## Demonstrated flow

1. A merchant payment-operations user reviews 10 fictional failed payments.
2. The user selects an eligible record and grants microphone access.
3. The backend generates a short-lived ElevenLabs WebRTC token without exposing the API key.
4. ElevenLabs receives customer and payment context through dynamic variables.
5. The browser shows a live transcript and synchronizes the final conversation outcome.
6. The customer opens `/pay/[case-id]`.
7. Razorpay Test Mode creates an order and presents hosted checkout.
8. Checkout signature verification or a signed `payment.captured` webhook marks the case recovered.
9. The dashboard reports confirmed recovered revenue separately from conversational intent.

Browser voice uses the 15 call minutes included in the ElevenLabs free tier. Optional PSTN integration remains implemented behind the `/api/calls` adapter, but a carrier such as Twilio can require account funding.

## Technology

- Next.js and TypeScript
- ElevenLabs ElevenAgents WebRTC browser voice
- Optional ElevenLabs + Twilio PSTN adapter

## Local setup

### 1. Install and configure

```powershell
Copy-Item .env.example .env.local
npm install
```

Fill `.env.local` with your own test credentials. Never commit `.env.local`, API keys, phone numbers, or webhook secrets.

### 2. Create Supabase tables

Create a Supabase project, open the SQL Editor, and run:

```text
supabase/schema.sql
```

Use the project URL and service-role key for `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. The service-role key is server-only and must never use a `NEXT_PUBLIC_` prefix.

If Supabase is not configured, the app uses a process-local store. This is useful for local demonstration but is not durable across server restarts or Vercel instances.

### 3. Configure free ElevenLabs browser voice

1. Create an ElevenLabs API key with ElevenAgents read/write access.
2. Set `ELEVENLABS_API_KEY` in `.env.local`.
3. Run:

   ```powershell
   npm run provision:voice
   ```

   This creates or reuses the RecoverAI agent, enables authenticated browser sessions, and stores `ELEVENLABS_AGENT_ID` locally.
4. Browser sessions use short-lived WebRTC tokens generated by the server. The API key is never sent to the browser.
5. For deployed post-call processing, add this ElevenLabs webhook:

   ```text
   https://YOUR_HOST/api/webhooks/elevenlabs
   ```

6. Enable `post_call_transcription`, configure HMAC authentication, and copy its secret to `ELEVENLABS_WEBHOOK_SECRET`.

Twilio credentials and `AUTHORIZED_DEMO_PHONE_NUMBER` are optional unless you intentionally enable the paid PSTN adapter. They are not required for the free browser-voice demonstration.

### 4. Configure Razorpay Test Mode

1. Switch the Razorpay Dashboard to **Test Mode**.
2. Generate test API keys and set `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET`.
3. Create a webhook with a separate secret:

   ```text
   https://YOUR_HOST/api/webhooks/razorpay
   ```

4. Enable the `payment.captured` event and set `RAZORPAY_WEBHOOK_SECRET`.

The payment page verifies the Razorpay Checkout response signature immediately and fetches the payment status from Razorpay. Revenue is counted as recovered only when the payment is captured; the signed webhook remains the durable, idempotent status source.

### 5. Run

```powershell
npm run dev
```

Open `http://localhost:3000`.

## Vercel deployment

1. Push the repository to a private or public GitHub repository.
2. Import it into Vercel.
3. Add every variable from `.env.example` in Vercel Project Settings.
4. Set `NEXT_PUBLIC_APP_URL` to the production Vercel URL.
5. Redeploy after changing environment variables.
6. Configure the ElevenLabs and Razorpay webhook URLs with the deployed HTTPS URL.
7. Run one browser voice session and one Razorpay test transaction before recording the demonstration.

## Workflow demonstration 

1. Show the outstanding amount and 10 fictional scenarios.
2. Select Rahul Mehta and click **Start browser voice session**.
3. Grant microphone access and speak directly with the ElevenLabs agent.
4. Confirm identity, explain that funds are now available, and request a secure link.
5. End the session and show the synchronized transcript and outcome.
6. Open the secure payment page and complete a Razorpay test payment.
7. Return to the dashboard and show the case counted as recovered only after confirmation.
8. Briefly shows wrong-person, dispute, cancellation, callback, and opt-out scenarios in the dataset.

## Safety and compliance guardrails

- The agent identifies itself as automated.
- Payment details are disclosed only after confirming the intended person.
- The agent never requests OTPs, UPI PINs, card PINs, CVVs, full card numbers, or banking passwords.
- Browser voice starts only after explicit microphone permission.
- The application does not record browser audio.
- Opted-out and recovered records cannot start another recovery session.
- Disputes and reports of an existing payment are escalated rather than retried.
- Payment success is never inferred from a conversation.
- Razorpay and ElevenLabs webhooks require signatures and support idempotent processing.

## Assumptions and limitations

- All names, merchants, subscriptions, failures, transcripts, and payment records are fictional.
- This is a hackathon prototype, not a production debt-collection system.
- The free demonstration is browser-based rather than a PSTN phone call.
- ElevenLabs free-plan minutes and any separate LLM allowance remain subject to current account limits.
- Calling Indian numbers through the optional PSTN adapter requires carrier billing, destination permissions, regulatory configuration, and compliant calling hours.
- The agent starts in English and can follow a customer into Hindi/Hinglish, subject to the configured ElevenLabs model and voice.
- The voice agent sends customers to hosted checkout; it does not collect payment credentials by voice.
- Production use would require merchant authentication, role-based access, consent and suppression policies, rate limits, audit retention rules, observability, and legal/compliance review.
- Automatic recurring-payment retry coordination is simulated. A production system must prevent duplicate collection between provider retries and customer-initiated payments.
